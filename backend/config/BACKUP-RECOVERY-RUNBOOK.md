# Backup, recovery and retention runbook

MongoDB is the system of record. Production must use the managed backup capability of the deployed MongoDB service; the application does not copy database credentials or export backups itself. Configure continuous or scheduled encrypted backups with an effective recovery-point objective no greater than `BACKUP_RPO_MINUTES`, retain recovery points for at least `BACKUP_RETENTION_DAYS`, and restrict restore permissions to the operations role.

Set `BACKUP_ENABLED=true` only after backups are visible and a restore into an isolated database has succeeded. Never restore over production during a drill. Validate document counts, critical indexes, TTL indexes, authentication isolation and a representative read after restoration. Record the drill through `POST /api/v1/admin/recovery-drills`; store timestamps and outcome only, never connection strings, credentials, CV contents or tokens. `GET /api/v1/admin/production-readiness` fails the release gate when the latest successful drill is stale, exceeds RPO/RTO, or unresolved dead-letter work remains.

Retention is enforced by MongoDB TTL indexes and a daily idempotent `data-retention` worker for legacy rows. Audit records default to 365 days and operational worker/ingestion records default to 90 days. Candidate CV retention continues to use the existing CV deletion worker and provider deletion receipts. Legal holds and statutory retention changes require an approved configuration change; do not silently extend or shorten production retention.

For an incident: stop writers, preserve audit evidence, select the newest valid recovery point before the incident, restore to an isolated database, validate it, then switch application configuration through the deployment secret manager. Roll back by restoring the previous database target and application release. Revoke any credentials suspected of compromise. Health endpoints contain no provider details: `/api/v1/health/live` confirms the process and `/api/v1/health/ready` confirms persistence.
